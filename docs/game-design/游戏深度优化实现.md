# 游戏深度优化实现

本轮以“空间 + 商品 + 信息 + 时间 + 风险”为主轴，把原本相对独立的交易、探索与加工接入同一个中期决策循环。

## 已实现范围

1. 探索深度：逐层成长、每 3 层精英、每 7 层首领、递增掉落和随时撤退。
2. 动态市场与城市差价：风栖镇和铁砧城拥有相反的基础供需，交易全程使用本地行情价。
3. 七日城市周期：固定日期事件、提前公告、周期第 7 天开放商路。
4. 背包 Build：多武器轮换、矿石/力量药剂相邻加成、腰包区免费使用消耗品。
5. 顾客关系与情报：成功交易提升关系，高关系提前揭示事件。
6. 商车模块：车顶货架、隐藏夹层、行军灶，三选二形成长期 Build。
7. 首批内容：第二座城市、四类事件、精英层与首领层，足以验证两个完整周期的闭环。

## 关键闭环

查看公告 → 决定囤货与加工 → 通过经营或探索获取商品 → 布置背包 Build 并判断撤退深度 → 利用事件需求出售 → 承受本地市场饱和 → 第 7 天选择留城或跨城套利 → 用利润购买改变规则的商车模块。

## 实现位置

- `scripts/city_economy.gd`：城市、事件、价格、供给压力、关系、情报与模块。
- `scripts/trade_state.gd`：行情进入报价、结算、日推进和旅行。
- `scripts/exploration_state.gd`：深度、精英、首领、掉落和背包联动。
- `scripts/shop.gd`、`scripts/exploration.gd`：行情板、改装入口与局内反馈。
- `tests/test_game_depth.gd`：跨系统规则验收。
- `scripts/market_board.gd`：逐物品行情、价格分解和事件精确预测。
- `scripts/module_shop.gd`：模块前后对比、购买状态和即时生效反馈。
- `tests/test_game_depth_ui.gd`：行情、改装与背包反馈的界面数据验收。

## 可见反馈原则

- 玩家看到的行情现价、柜台议价基准和战败保护排序必须来自同一计算结果。
- 事件不只显示类别或模糊趋势，必须列出具体物品、事件倍率和预测价格。
- 背包联动必须同时提供空间连线、短徽标、组合汇总和悬停详值。
- 模块必须显示改装前后差异，并在安装后留下持续可见的结果证据。
