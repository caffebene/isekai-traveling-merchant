# 战斗场景过渡修正经验

## 最终方案

- 战斗场景由 `scenes/battle_multilayer.tscn` 和 `scripts/battle_space_loop.gd` 独立负责，只替换场景画面，不把 UI、角色或战斗状态放进 3D 场景。
- Camera 保持固定，前进时让 8 个场景层连续向镜头移动一个间距；新增的第 9 层使用 `TransitionGhost` 在队尾淡入。
- 首层淡出、新增第 9 层淡入和层队列提交必须使用同一个过渡进度，不能在 Near Clip、相机距离或怪物生成时额外触发换层。
- 探索逻辑在前进动画达到终点后先标记 `travel_finish_pending`，等待 3D 场景完成提交，再调用 `combat.next_encounter()` 生成怪物。

## 两个关键材质问题

### `Sprite3D.modulate` 不一定能控制自定义材质透明度

如果 Sprite3D 使用 `StandardMaterial3D` 覆盖材质，需要设置：

```gdscript
material.transparency = BaseMaterial3D.TRANSPARENCY_ALPHA
material.vertex_color_use_as_albedo = true
```

否则代码虽然改变了 `modulate.a`，材质仍可能按 100% 不透明绘制，表现为新增层一开始突然出现、首层直到最终提交才突然消失。

### 动态替换纹理必须同步材质纹理

`TransitionGhost` 每次复用时，不能只设置 `ghost.texture`，还必须同步 `StandardMaterial3D.albedo_texture`。否则第二次及后续过渡中，Ghost 淡入的画面和提交后的实际层画面不同，也会在提交帧产生突变。

## 排查顺序

1. 先确认前进开始后的首层和 Ghost 的 `modulate.a` 是否连续变化。
2. 再确认自定义材质开启 Alpha 透明和顶点颜色参与 Albedo。
3. 对比提交前后首层、队尾层的纹理、位置、`pixel_size` 和透明度。
4. 确认怪物生成不与层队列提交发生在同一套状态切换之前。
5. 连续测试至少两次前进，因为 Ghost 材质未同步通常只会在第二次及以后暴露。
